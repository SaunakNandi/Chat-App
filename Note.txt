Specifies the API endpoint (/api/v1/chat/my).

credentials: "include" ensures that authentication tokens (cookies, sessions, JWTs) are sent with the request.

providesTags: ["Chat"]
Caches the response under the "Chat" tag.
If another API call invalidates "Chat", RTK Query automatically refetches the latest data.

Invalidation in RTK Query means marking cached data as stale so that it triggers a refetch on the next request.

createApi() automatically generates React hooks for each query/mutation.
Since you defined myChats: builder.query(...), RTK Query creates
useMyChatsQuery = api.endpoints.myChats.useQuery;

useMyChatsQuery
This is a custom hook that:
Fetches data from /api/v1/chat/my.
Uses caching, re-fetching, and state management automatically.

useMyChatsQuery is an auto-generated hook by RTK Query.


=> How It Works Step-by-Step
User loads the chat layout.
useMyChatsQuery() fetches chat data from GET /api/v1/chat/my.
If the response is cached (from a previous request), it is instantly available.
If not, Redux Toolkit Query:
Sends an API request.
Stores the result in Redux state.
Caches it with the "Chat" tag.
The ChatList component displays the fetched chat list.
If a new friend is added, the "Chat" tag gets invalidated, automatically refetching the chat list.


=> Key Benefits of This Approach
✅ Automatic Caching – Prevents redundant API calls.
✅ Tag-Based Invalidation – Ensures fresh data when needed(when a get or post call is made).
✅ Efficient State Management – Data is stored in Redux and auto-updates the UI.
✅ Simplified API Handling – No need for manual useState/useEffect.

import { useEffect, useState } from "react";

const useInfiniteScrollTop = (containerRef, totalPages, page, setPage, newData, shouldReverse = false) => {
    const [data, setData] = useState([]);

    useEffect(() => {
        const container = containerRef.current;
        if (!container) return;

        const handleScroll = () => {
            if (container.scrollTop === 0 && page < totalPages) {
                setPage((prevPage) => prevPage + 1);
            }
        };

        //  handleScroll runs every time the user scrolls.
        container.addEventListener("scroll", handleScroll);
        return () => container.removeEventListener("scroll", handleScroll);
    }, [containerRef, page, totalPages, setPage]);

    useEffect(() => {
        if (newData && newData.length > 0) {
            setData((prev) => (shouldReverse ? [...newData, ...prev] : [...prev, ...newData]));
        }
    }, [newData, shouldReverse]);

    return { data, setData };
};


When you scroll inside the containerRef, these properties get updated:

containerRef.current.scrollTop → Changes dynamically as you scroll up/down.
containerRef.current.scrollHeight → Remains the same unless new content is loaded.
containerRef.current.clientHeight → Remains constant (unless resized).




// Note 3
The reason your frontend socket.on(NEW_MESSAGE, newMessagesListner) only listens when the server emits NEW_MESSAGE, but not when the client emits it, is because:

Socket.io doesn't listen to events emitted by itself – When you call socket.emit(NEW_MESSAGE, { chatId, members, message }) on the client, that event is sent to the server, not to the same client. The socket.on(NEW_MESSAGE, newMessagesListner) on the client will only run when the server emits NEW_MESSAGE.

Server receives and re-emits the event – Your server listens for NEW_MESSAGE, processes it, and then emits it to the relevant sockets (io.to(membersSocket).emit(NEW_MESSAGE, {...})). This is when your client-side listener picks it up.
